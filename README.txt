TRACK A RUN
1. Optionally enter map, class/job, and level. Starting EXP is within-level EXP when a level is provided.
2. Choose Use screenshot to start. Review its recognized values and confirm once; a complete starting review starts the timer immediately. If a required value is missing, Manual values opens with a validation message. You can also open Manual values to enter starting EXP, mesos, supplies, quantities and editable unit prices, then start from that form. Choose ETC targets there before reading a screenshot. Use slots start with Meat (80 mesos) and Lemon (150 mesos); add/remove slots for other consumables, including buff items (up to 12 unique items). New sessions remember the selected items, shortcut regions, readers and unit prices in this browser, including after refresh; session quantities and balances reset. Saved choices take precedence over these initial defaults.
3. Pause/resume for breaks. At setup, optionally choose Auto-detect break time with automatic screenshots: two readable EXP captures without a gain pause active time, and the next readable gain resumes it. Unreadable EXP does not count. Manual pause still stops automatic screenshots. Optional checkpoints record snapshots for the final pace review.
4. Done stops active time, including when paused. Enter ending values and ending level if supplied at the start.
5. Adjust cumulative supply additions. Without level metadata, the manual extra-EXP field supports legacy sessions.
6. Optionally add unsold loot estimates or income/expenses not already in your entered balance. Calculate.
7. The run saves to history automatically. Editing ending values updates the same record.

INSIGHTS
Rates per hour, 10 minutes, and minute; automatic EXP across levels; target-level ETA; 30/60-minute projections; Per-item usage per minute; supply cost/hour and remaining training time; 10-active-minute checkpoint reminder; interval pace chart; saved session review; class/starting-level filters; time-weighted map averages; EXP-versus-profit chart; JSON backup/restore; CSV export.

FORMULAS
Original net = ending mesos - starting mesos - sum(used quantity * unit cost for every tracked Use item).
Legacy two-supply recordings retain the original HP/MP formula.
Adjusted cash net = original net + income not in balance - expenses not in balance.
Estimated total net = adjusted cash net + estimated unsold loot.
Used = starting + cumulative additions - ending quantity.
Automatic EXP = ending cumulative level/EXP position - starting position.
Legacy EXP = ending EXP - starting EXP + manual EXP requirements of levels completed.
Rate = gain * target duration / active duration. Breaks and ending-value entry are excluded.

Buy supplies before starting. In-run purchases already reduce the meso balance and can be counted twice by the requested original formula. Do not also enter sales/expenses in the ledger if reflected in your ending balance. Count mixed HP/MP recovery items in one slot only.

EXP FONT READER
EXP defaults to Classic EXP digits, reading the HUD percentage rather than the absolute counter. The font matcher requires a complete decimal percentage plus the percent glyph and ignores the absolute-number prefix before the green bracket. General text OCR supports the same percentage conversion. The potion digit template cannot read the decimal percentage; choose EXP digits or General text OCR for this preset. Other fields can still use the original whole-number EXP font reader.
Estimated within-level EXP = floor(EXP required for the captured level * displayed percent / 100). Conversion uses integer basis points to avoid floating-point rounding surprises. Example: level 58 requires 1,087,536 EXP; 24.70% gives an estimate of 268,621. Display percentages have only two decimal places, so an exact EXP total cannot be recovered. Review explicitly labels this approximation; users can enter an exact total manually. Editing/selecting the reviewed level recalculates percentage-derived EXP, including selected-field rereads. Missing levels leave the estimate blank; automatic capture requires a fresh level reading from the same image and never assumes the starting level across a level-up. Level 100 accepts only 0.00%/0 EXP.
Local font metadata: dist/data/exp-font.json. Ten 5x7 digits plus the 7x7 percent sprite are stored in dist/assets/exp-font/, from https://maplestory.io/api/wz/GMS/83/UI/StatusBar.img/number (Nexon game assets). build-exp-font.cjs validates SHA-256/dimensions and generates exp-font.js. exp-reader.js runs in a cancellable worker and is embedded into the standalone download. No screenshots or recognition requests are sent to the sprite provider.
node test-exp-reader.cjs retains 38 whole-number font regression fixtures for other presets. node test-exp-percent.cjs covers real and clipped-prefix percentage crops, 35 rendered scale fixtures, incomplete percentages, conversion/rounding, level-up/rate math, agreement and region migration. Background OCR tests exercise real percentage/level-to-EXP conversion alongside unchanged HP/MP matching. Synthetic fixtures use native sprites and bilinear scaling without image-library dependencies.

Automatic progress (screen snapshots)
During a running session with a starting level, toggle Auto screenshots. Choose Entire screen / monitor (Screen 1 or Screen 2 in Firefox). A reload needs a fresh opt-in and browser permission. Throttled/sleeping browsers can run late; timestamps are taken at actual capture time, paused time is excluded and missed minutes are never replayed.
Each sample is quality-checked (font matcher result or text OCR confidence/majority agreement), parsed and checked against level/EXP bounds. A pending sample is checked against later samples before becoming a checkpoint. Quantity increases, mesos/EXP decreases and isolated reversals are held or rejected. The exact 100 -> 95 -> 150 -> 85 pattern discards 150 when the trend returns. After three confirmed intervals, recent median rates and median absolute deviations flag extreme jumps for manual review. Unreadable inventory balances and supply counts are stored as null. Valid EXP continues even when a potion font cannot be read. Raw net mesos and supply cost require current supply counts; no last-known count is written into a checkpoint. The live dashboard separately forecasts missing financial components and labels them Estimated. Only complete confirmed snapshots become full financial checkpoints. Partial EXP points remain in automatic progress history and JSON. Readings are not interpolated or mixed across capture times. Plausible repeated OCR errors can still escape these heuristics.
Actual restocks, spending or EXP loss require a manual checkpoint (including cumulative added potions) to reset the baseline; no additions are inferred. Screen size or reader-layout changes stop automatic capture for recalibration. The latest 30 value-only sample decisions remain in the current draft; confirmed points use the normal checkpoint history and JSON export. The latest unconfirmed sample is excluded. Done prefills the final form from the last confirmed automatic checkpoint, which may be older than the stop time: the user must update/review actual ending totals, add ETC, and submit.
