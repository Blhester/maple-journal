MAPLE JOURNAL — MapleStory Classic grind journal

Open dist/index.html directly, or run node preview.cjs and visit http://127.0.0.1:4173.
No installation or build is needed. Calculations work offline; Google Fonts fall back to system fonts.
The header slider remembers light/dark mode, including sun/moon icons.

TRACK A RUN
1. Optionally enter map, class/job, and level. Starting EXP is within-level EXP when a level is provided.
2. Enter starting EXP, mesos, supplies, quantities, and editable unit prices. Start the timer. The initial HP/MP defaults are Meat (80 mesos) and Lemon (150 mesos). New sessions remember the last selected HP/MP items and unit prices in this browser, including after refresh; session quantities and balances reset. Saved choices take precedence over these initial defaults.
3. Pause/resume for breaks. Optional checkpoints record snapshots for the final pace review.
4. Done stops active time, including when paused. Enter ending values and ending level if supplied at the start.
5. Adjust cumulative supply additions. Without level metadata, the manual extra-EXP field supports legacy sessions.
6. Optionally add unsold loot estimates or income/expenses not already in your entered balance. Calculate.
7. The run saves to history automatically. Editing ending values updates the same record.

INSIGHTS
Rates per hour, 10 minutes, and minute; automatic EXP across levels; target-level ETA; 30/60-minute projections; HP/MP usage per minute; supply cost/hour and remaining training time; 10-active-minute checkpoint reminder; interval pace chart; saved session review; class/starting-level filters; time-weighted map averages; EXP-versus-profit chart; JSON backup/restore; CSV export.

FORMULAS
Original net = ending mesos - starting mesos - HP used * HP cost - MP used * MP cost.
Adjusted cash net = original net + income not in balance - expenses not in balance.
Estimated total net = adjusted cash net + estimated unsold loot.
Used = starting + cumulative additions - ending quantity.
Automatic EXP = ending cumulative level/EXP position - starting position.
Legacy EXP = ending EXP - starting EXP + manual EXP requirements of levels completed.
Rate = gain * target duration / active duration. Breaks and ending-value entry are excluded.

Buy supplies before starting. In-run purchases already reduce the meso balance and can be counted twice by the requested original formula. Do not also enter sales/expenses in the ledger if reflected in your ending balance. Count mixed HP/MP recovery items in one slot only.

STORAGE
History, the active draft/checkpoints, and theme stay in this browser. The hosted site, localhost, and local-file copy use separate origin storage. No game/account connection or server-side history storage is used. Back up important runs with JSON. Restore JSON replaces saved history with the backup, including removing sessions absent from it; an empty backup clears history. The whole file is validated and saved before the visible history changes. Restores reset history filters and synchronize other open tabs. The current tracker draft stays separate and is only added to history when explicitly calculated. Filters do not limit exports. Comparisons do not normalize party size, gear, buffs, or map changes during a run.

ETC DROPS
After Done, search the local ETC catalog by name, select an icon/name/price result, and enter the number of individual items gained (not the number of stacks). Repeated additions of the same item and sale status merge. Quantities and sale status remain editable.
Unsold drops add quantity × NPC vendor price to estimated total net. Drops sold after recording the ending balance add to adjusted cash net instead. Exclude drops already reflected in the ending mesos to avoid counting them twice. The review defaults to total net with loot when unsold drops exist; Profit shown switches the main total and all three meso rates between the original formula, adjusted cash, and loot-inclusive total. Projections and checkpoint trends continue to use original net as labeled.
ETC quantity, unit-price snapshots, sale status, and names survive session edits, refresh, saved reviews, JSON backups/restores, and CSV summaries. Existing saved sessions remain compatible.

OCR IMAGE ADJUSTMENTS
Select a read region, then open Improve a difficult read. EXP and supply counts offer Number recognition: Classic EXP digits / Classic potion digits, or General text OCR. In General text OCR, compare the original enlarged crop with the processed preview. Choose white text, neutral white text (removes color using color tolerance), dark text, gold/orange, or grayscale. Contrast, brightness, threshold, enlargement (2–6x), and inversion update the preview on this device. Grayscale does not use threshold; only the neutral filter uses color tolerance. Enlargement is capped for unusually large regions to limit canvas memory.
Re-read selected field uses that exact processed preview with several line/word segmentation modes. It replaces only that field's proposal and preserves other reviewed values and supply choices. Conflicting valid readings appear as selectable alternatives; neither an alternative nor OCR confidence guarantees correctness. Adjusting a field's crop/image settings unchecks its old proposal until reread or edited. Standard Read screenshot keeps the original automatic treatments for untouched fields and uses your adjusted image settings for fields you customized.
Remember regions & image settings stores coordinates and filter values locally; it does not save screenshot pixels. Reset this field's image settings clears one field's tuning, and Reset example settings clears remembered regions and tuning. HP/MP default to Classic potion digits, which matches the original colored crop against the game's ten quantity sprites instead of general OCR. The example now reads 441/761. Sliders are hidden in this mode because matching needs the original outline and blue shading. Use Recognition reader > General text OCR for other fonts. An ambiguous/unsupported match stays blank; it never falls back to a misleading Tesseract count. Keep the complete number in the region, with a little space at each edge. Other screenshots/resolutions still require review.
Preprocessing and segmentation guidance: https://tesseract-ocr.github.io/tessdoc/ImproveQuality.html and https://github.com/naptha/tesseract.js/blob/master/docs/api.md

OCR MAP MATCHING
The training-map reader compares every OCR pass against a local snapshot of MeowDB Classic's 424 named English map records (429 source rows; five unnamed numeric placeholders excluded) (https://meowdb.com/msclassic/maps). It ranks map names with edit/transposition similarity and street context, preserves numbered map suffixes, and deduplicates identical display labels. Up to two real catalog names are offered; a weak or close match is unchecked until chosen. Unrelated text produces no match. Similarity cannot guarantee the true location is among two suggestions.
Search the map input for another catalog entry. Screenshot import accepts only a resolved catalog name, stored as Street · Map; arbitrary OCR text is preserved in Recognized text, never silently applied as a map. Manual tracker entry and existing history remain compatible with custom names. No historical sessions are renamed.
The checked-in catalog is dist/data/maps.json; build-maps.cjs generates dist/map-data.js. Run node refresh-map-catalog.cjs to intentionally refresh from the public rendered map index; it parses JSON data without executing source scripts and fails if the source format changes. Matching, search, and standalone imports work offline; no screenshot or OCR text is sent to MeowDB. No new keys or AWS variables are needed.

EXP FONT READER
EXP defaults to Classic EXP digits, matching the GMS v83 status-bar number sprites independently of the potion quantity font. The local matcher fits scaled/antialiased digit silhouettes, handles thousands separators and zero, and excludes the percentage after the green opening bracket. Automatic progress (screen snapshots)
During a running session with a starting level, toggle Auto screenshots. Choose Entire screen / monitor (Screen 1 or Screen 2 in Firefox). Reported window and browser-tab sources are rejected and stopped. Firefox does not advertise displaySurface support and can omit source-type metadata: these streams are accepted, with instructions to select a full screen; the app cannot independently verify that choice. Unknown sources from browsers advertising displaySurface support (or lacking feature detection) are rejected. displaySurface is a preference, so the browser picker itself can still display other choices. No window API, game hooks, process reads or input automation are used. This cannot guarantee compatibility with a game's anti-cheat rules.
The browser monitor stream stays connected, requested at at most 1 frame/second with no audio; the app encodes one PNG immediately and then about every 60 seconds. No video is recorded. The numeric HUD regions are recognized (level, EXP and both supplies are required; mesos is optional) using the saved per-field reader/filter settings. Check screenshot regions & readers opens a calibration-only preview during training (and stops automatic mode first); it cannot apply values to the starting/ending form. Read regions must be calibrated against a full-screen capture, and inventory mesos / both supply slots must stay visible. Pixel buffers, image URLs and OCR workers are released after each job. Screenshot pixels are never saved, uploaded or included in history/JSON.
Only one job runs at a time, with a 45-second deadline. Pausing skips captures; stopping sharing, turning the mode off, Done, discard, page exit or permission denial ends capture. A reload needs a fresh opt-in and browser permission. Throttled/sleeping browsers can run late; timestamps are taken at actual capture time, paused time is excluded and missed minutes are never replayed.
Each sample is quality-checked (font matcher result or text OCR confidence/majority agreement), parsed and checked against level/EXP bounds. A pending sample is checked against later samples before becoming a checkpoint. Quantity increases, mesos/EXP decreases and isolated reversals are held or rejected. The exact 100 -> 95 -> 150 -> 85 pattern discards 150 when the trend returns. After three confirmed intervals, recent median rates and median absolute deviations flag extreme jumps for manual review. Unreadable inventory balances are stored as null, with EXP/supply progress continuing independently. Readings are not interpolated or mixed across capture times. Plausible repeated OCR errors can still escape these heuristics.
Actual restocks, spending or EXP loss require a manual checkpoint (including cumulative added potions) to reset the baseline; no additions are inferred. Screen size or reader-layout changes stop automatic capture for recalibration. The latest 30 value-only sample decisions remain in the current draft; confirmed points use the normal checkpoint history and JSON export. The latest unconfirmed sample is excluded. Done prefills the final form from the last confirmed automatic checkpoint, which may be older than the stop time: the user must update/review actual ending totals, add ETC, and submit.

Live training dashboard
The initial form validates starting values once. Start automatic screenshots after validation is checked by default when screen capture and a starting level are available; uncheck it for manual entry. The running session hides the starting form and shows EXP/hour and net-mesos/hour charts plus current level/EXP, EXP gained, net mesos, HP/MP remaining, potion cost and time to next level. Rates are session averages evaluated at each actual capture time, with paused time excluded. They can rise or fall.
Plausible latest captures appear immediately as hollow/dashed pending points. They are excluded from saved confirmed history until the next reading validates them. Held/rejected samples are not shown as trusted readings. Mesos validation is independent: hidden/uncertain balances or mesos spikes become N/A while EXP/supplies continue. Missing values create chart gaps; zeros stay valid zeros. Net rates include potion costs using validated starting item prices; ETC remains manual at final review.

Live graphs begin with a zero-rate point at active time zero. Live EXP/hour and readable net-mesos/hour stay at 0 until a usable capture at or beyond 60,000 active milliseconds. The Gathering first minute label distinguishes this warmup from a measured zero rate. This prevents a 2-meso difference in a 120 ms startup capture from displaying 60,000 mesos/hour. Captured totals, validated starting values, missing-balance N/A behavior and final reviewed session calculations are preserved. Early confirmed points and restored drafts use the same warmup rule; the synthetic origin is never saved as a checkpoint.
A pale neutral background check on the original calibrated mesos region helps reject scenery digits when inventory is closed. Keep white inventory-bar padding inside that crop; uncertain/unsupported appearance defaults to N/A. This cue and OCR are heuristics, not a guarantee of inventory detection. Reopen the inventory for readable balance samples. No stale balance is carried into a later capture.

Classic potion matching includes a small margin of actual neighboring screenshot pixels around the selected region. This recovers outlines touching a tightly drawn crop without changing the matcher thresholds or saved coordinates. It applies in manual and automatic capture; EXP and general OCR crops are unchanged. A rejected font read shows its specific reason in the review instead of only a generic blank-result message. Include the full number and avoid adjacent stack counts.
Confirmed automatic samples, including null mesos, persist in autoPoints in drafts/history/JSON. Full numeric checkpoints remain compatible with existing calculations. Restoring a draft restores confirmed graphs with capture off; pending previews do not survive reload. The final form uses the freshest confirmed values and leaves an unknown balance blank for human validation.
